# 7. Dark and light mode are FIRST-CLASS requirements

MAYOS must support both:

* Dark Mode
* Light Mode

This is not cosmetic and is not optional.

Theme switching is a fundamental product requirement.

Neither theme may be treated as an afterthought.

Dark mode should feel:

* deep
* focused
* premium
* athletic
* cinematic without becoming theatrical

Light mode should feel:

* sophisticated
* spacious
* clean
* warm enough to avoid looking sterile
* clearly related to the dark design

Do not simply invert colors.

Create semantic theme tokens.

For example:

```dart
abstract final class MayosColors {
  // semantic tokens / palettes rather than screen-specific colors
}
```

Use Flutter's `ThemeData` / `ColorScheme` appropriately, while allowing MAYOS-specific semantic extensions if necessary.

Strongly consider a `ThemeExtension` for MAYOS-specific colors that don't belong naturally in Material's default color scheme.

For example:

```dart
@immutable
class MayosThemeExtension extends ThemeExtension<MayosThemeExtension> {
  // surface layers
  // success
  // warning
  // training states
  // muted text
  // chart colors
}
```

Do not scatter literal hex colors throughout widgets.

You are allowed to significantly redesign presentation widgets.

If an existing widget prevents the desired MAYOS visual language, replace/refactor it cleanly.

Do not preserve bad presentation purely for minimal diff size.

At the same time, don't unnecessarily rewrite working domain/application code.
